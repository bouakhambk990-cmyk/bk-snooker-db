# 🎱 BK Snooker Club — POS V4 Professional

ລະບົບຂາຍໜ້າຮ້ານ (POS) ສຳລັບຮ້ານສະນຸກເກີ/ບິນລຽດ — ຈັດການໂຕະ, ບິນ, ສະຕັອກ, ສະມາຊິກ, ການເງິນ ແລະ ລາຍງານ.
ເປັນແອັບແບບ **ໄຟລ໌ດຽວ (single-page app)** ຂຽນດ້ວຍ HTML/CSS/JavaScript ລ້ວນໆ, ບໍ່ຕ້ອງມີ backend, ບໍ່ຕ້ອງ build,
ແລະ ຮອງຮັບການໃຊ້ແບບ **PWA** (ຕິດຕັ້ງເປັນແອັບ, ໃຊ້ offline ໄດ້).

## 📱 WhatsApp — ສົ່ງໃບເສັດຫາລູກຄ້າ (ປັບປຸງໃໝ່)

ແກ້ບັນຫາທີ່ຕ້ອງພິມເບີລູກຄ້າຊ້ຳທຸກຄັ້ງ — ຕອນນີ້ໃນໜ້າໃບເສັດ (ຫຼັງຊຳລະສຳເລັດ):

  ໂດຍບໍ່ຕ້ອງພິມຄືນໃໝ່
- **ເພີ່ມເບີໄດ້ຫຼາຍເບີ** — ພິມເບີເພີ່ມ ແລ້ວກົດ "+ ເພີ່ມເບີ" ໄດ້ຫຼາຍຄັ້ງ ເໝາະສຳລັບກໍລະນີມີລູກຄ້າ 2-3 ຄົນຢູ່ໂຕະ
  ດຽວກັນ ຢາກສົ່ງໃບເສັດໃຫ້ທຸກຄົນ
- ກົດ **"📱 ສົ່ງ WhatsApp (N)"** ຄັ້ງດຽວ ຈະເປີດ WhatsApp ສົ່ງໃຫ້ທຸກເບີໃນລາຍຊື່ (ໜ່ວງເວລາເລັກນ້ອຍລະຫວ່າງແຕ່ລະ
  ໜ້າຈໍເພື່ອບໍ່ໃຫ້ browser ບລັອກ popup)
- ສາມາດກົດ ✕ ຢູ່ chip ເພື່ອລຶບເບີທີ່ບໍ່ຕ້ອງການອອກໄດ້

## 🎮 ຄິດໄລ່ລາຄາຕໍ່ເກມ (Per-game pricing)

ນອກຈາກຄິດຄ່າໂຕະ **ຕໍ່ຊົ່ວໂມງ** (ແບບເດີມ), ຕອນນີ້ແຕ່ລະໂຕະສາມາດຕັ້ງໃຫ້ຄິດຄ່າ **ຕໍ່ເກມ** ໄດ້ ແລະ ແຕ່ລະໂຕະ
ຕັ້ງລາຄາ/ໂໝດແຕກຕ່າງກັນໄດ້ ເຊັ່ນ: ໂຕະ 1 = ຕໍ່ເກມ (1 ເກມ = 5,000 ກີບ), ໂຕະ 2 = ຕໍ່ຊົ່ວໂມງ.

**ວິທີຕັ້ງຄ່າ:**
1. ໄປໜ້າ **⚙️ ຕັ້ງຄ່າ** → ກ່ອງ **"🎮 ຄິດໄລ່ລາຄາແຕ່ລະໂຕະ"**
2. ສຳລັບແຕ່ລະໂຕະ ເລືອກ **⏱ ຕໍ່ຊົ່ວໂມງ** (ໃຊ້ລາຄາລວມທີ່ຕັ້ງໄວ້ຂ້າງເທິງ) ຫຼື **🎮 ຕໍ່ເກມ** (ໃສ່ລາຄາ/ເກມສະເພາະໂຕະນັ້ນ)
3. ກົດ **ບັນທຶກລາຄາທຸກໂຕະ**

**ວິທີໃຊ້ໜ້າງານ:** ເປີດໂຕະທີ່ຕັ້ງເປັນ "ຕໍ່ເກມ" ຕາມປົກກະຕິ → ໃນໜ້າໂຕະຈະມີປຸ່ມ **− / +** ໃຫ້ນັບຈຳນວນເກມ,
ຍອດເງິນຄິດອັດຕະໂນມັດ = ຈຳນວນເກມ × ລາຄາ/ເກມ (2 ເກມ = 10,000 ກີບ ຖ້າຕັ້ງ 5,000/ເກມ). ຈຳນວນເກມຈະຣີເຊັດເປັນ 0
ອັດຕະໂນມັດທຸກຄັ້ງທີ່ເປີດໂຕະໃໝ່ ຫຼື ຫຼັງຈ່າຍບິນສຳເລັດ.

## 🛠️ ບັນຫາທີ່ພົບ ແລະ ໄດ້ແກ້ໄຂແລ້ວ (Bug fixes)

ໃນການກວດແກ້ຄັ້ງນີ້, ໄດ້ກວດສອບໂຄ້ດທັງໝົດດ້ວຍ syntax checker (Node.js) ແລະ ຈຳລອງການໃຊ້ງານຈິງ
ຜ່ານ headless browser (login → ເປີດໂຕະ → ສັ່ງອາຫານ → ຈ່າຍເງິນ → ລາຍງານ → ຕັ້ງຄ່າ ...) ເພື່ອກວດຫາ error,
ພ້ອມທັງກວດ logic ດ້ານການເງິນຢ່າງລະອຽດ. ພົບ ແລະ ແກ້ໄຂ **3 bug** ດັ່ງນີ້:

1. **ລາຄາຊ່ວງກາງຄືນ (Late-night price) ຄິດຜິດ** — ຖ້າລູກຄ້າເປີດໂຕະ *ຫຼັງຈາກ* ເວລາເລີ່ມລາຄາກາງຄືນໄປແລ້ວ
   (ຕົວຢ່າງ: ຕັ້ງເວລາກາງຄືນເລີ່ມ 22:00 ແຕ່ລູກຄ້າເປີດໂຕະ 23:00) ລະບົບເກົ່າຈະຄິດເປັນລາຄາປົກກະຕິ (ລາຄາທ່ຽງວັນ)
   ໝົດ session ແທນທີ່ຈະເປັນລາຄາກາງຄືນ — ເຮັດໃຫ້ຮ້ານເສຍລາຍຮັບ. ✅ ແກ້ໄຂໃຫ້ຄິດເປັນລາຄາກາງຄືນຖ້າເປີດໂຕະຫຼັງ
   ເວລາທີ່ຕັ້ງໄວ້ແລ້ວ.
2. **ຍອດເງິນສົດທີ່ຄາດວ່າຈະມີ (ປິດ shift) ຄິດຜິດ** — ຕອນປິດ shift, ຍອດ "ຄາດວ່າ" ໃນລີ້ນຊັກເງິນ ຄິດລວມ
   ຍອດຂາຍທີ່ຈ່າຍຜ່ານ **ໂອນ/QR** ນຳ, ຊຶ່ງເງິນນັ້ນບໍ່ໄດ້ເຂົ້າລີ້ນຊັກເງິນສົດຈິງ — ເຮັດໃຫ້ຄິດວ່າເງິນສົດຂາດເວລານັບຈິງ.
   ✅ ແກ້ໄຂໃຫ້ຄິດສະເພາະຍອດທີ່ຈ່າຍເປັນ "ເງິນສົດ" ເທົ່ານັ້ນ.
3. **ໝວດໝູ່ລາຍຈ່າຍບໍ່ສະແດງໃນລາຍງານ Shift (PDF)** — ໃນລາຍງານ shift, ຖັນ "ໝວດ" ຂອງລາຍຈ່າຍສະແດງ "-" ຕະຫຼອດ
   ເພາະໂຄ້ດອ້າງອິງຊື່ field ຜິດ (`e.cat` ທັງທີ່ຂໍ້ມູນຈິງເກັບໄວ້ໃນ `e.category`). ✅ ແກ້ໄຂໃຫ້ອ້າງອິງ field ຖືກຕ້ອງ.

ນອກນັ້ນ ໄດ້ກວດ syntax ທັງໝົດ (ບໍ່ພົບ error), ກວດການຊ້ຳກັນຂອງຟັງຊັນ, ແລະ ຈຳລອງຄລິກຜ່ານທຸກໆ tab/ໜ້າຈໍ
(Dashboard, ລາຍງານ, ປະຫວັດ, ສະມາຊິກ, ການເງິນ, ສະຕັອກ, ຕັດໃຊ້ພາຍໃນ, ຕັ້ງຄ່າ) — ບໍ່ພົບ error ໃນ console ອີກ.

## ☁️ Firebase Realtime Sync — sync ຂໍ້ມູນທັງໝົດ

ຕອນນີ້ POS ຕໍ່ສາຍກັບ **Firebase Realtime Database** ແລ້ວ, sync **ຂໍ້ມູນເກືອບທັງໝົດ** ຂອງລະບົບແບບ realtime
ຂ້າມອຸປະກອນ — ບໍ່ແມ່ນສະເພາະໂຕະອີກຕໍ່ໄປ:

- ໂຕະ (ສະຖານະ, ລາຍການ, ຈຳນວນເກມ), ບິນ/ປະຫວັດ, ສະຕັອກ, ສະມາຊິກ, ຄ່າໃຊ້ຈ່າຍ, Session, ຕັ້ງຄ່າຕ່າງໆ
  (ລາຄາ, Bundle Deal, Happy Hour, ຕັ້ງຄ່າໂຕະລາຍໂຕະ ...) — **ທຸກຢ່າງ sync ອັດຕະໂນມັດ** ທຸກຄັ້ງທີ່ມີການປ່ຽນແປງ
- ນອກຈາກນັ້ນ ທຸກຄັ້ງທີ່ກົດ "✅ ຢືນຢັນຊຳລະ" ບິນຈະຖືກສົ່ງເພີ່ມໄປ path `orders/{ເລກບິນ}` ນຳ (ສະດວກສຳລັບເບິ່ງ/
  ດຶງລາຍງານຈາກພາຍນອກ)
- **ທຸກໜ້າຈໍ/ອຸປະກອນທີ່ເປີດແອັບຢູ່ຈະເຫັນການອັບເດດທັນທີ** (ບໍ່ຕ້ອງກົດ refresh) — ເໝາະສຳລັບໃຊ້ຫຼາຍໜ້າຈໍ/Tablet
  ພ້ອມກັນ

> 🔒 **ຍົກເວັ້ນ** `users` (ລະຫັດຜ່ານຜູ້ໃຊ້) ແລະ `currentUser` (ເຊສຊັນລ໋ອກອິນ) — 2 ອັນນີ້ບໍ່ຖືກສົ່ງຂຶ້ນ Firebase
> ເລີຍ, ຄົງຢູ່ໃນ `localStorage` ຂອງແຕ່ລະເຄື່ອງເທົ່ານັ້ນ ເພື່ອຄວາມປອດໄພ. ແຕ່ລະອຸປະກອນຄຸ້ມຄອງການລ໋ອກອິນຂອງຕົນເອງ
> ເອງ — ລ໋ອກອິນຢູ່ອຸປະກອນໜຶ່ງ ຈະບໍ່ໄປລ໋ອກອິນອອກອຸປະກອນອື່ນ

### ⚠️ ຕ້ອງຕັ້ງຄ່າ Firebase Database Rules ກ່ອນໃຊ້ (ສຳຄັນຫຼາຍ!)

ໂດຍຄ່າເລີ່ມຕົ້ນ Firebase Realtime Database ອາດຈະຖືກລ໋ອກ (ປະຕິເສດການອ່ານ/ຂຽນທັງໝົດ) — ຖ້າເປັນແບບນັ້ນ ຟີເຈີ sync
ຈະບໍ່ເຮັດວຽກ (ຈະເຫັນ warning `permission-denied` ໃນ console). ໃຫ້ໄປທີ່ **Firebase Console → ໂປຣເຈັກ
`bk-snooker-db` → Realtime Database → ແທັບ Rules** ແລ້ວຕັ້ງເປັນ:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

**⚠️ ຄຳເຕືອນ:** rule ຂ້າງເທິງເປັນແບບ "ເປີດໝົດ" — ໝາຍຄວາມວ່າ **ໃຜກໍ່ຕາມທີ່ຮູ້ URL ຖານຂໍ້ມູນຂອງທ່ານສາມາດອ່ານ/ແກ້/
ລຶບຂໍ້ມູນໂຕະ ແລະ ບິນທັງໝົດໄດ້** ຜ່ານອິນເຕີເນັດ, ໂດຍບໍ່ຕ້ອງລ໋ອກອິນ. ເໝາະສຳລັບທົດສອບ/ຮ້ານນ້ອຍທີ່ຄວບຄຸມ URL
ໄດ້ເອງເທົ່ານັ້ນ. ຖ້າຈະໃຊ້ວຽນວຽນ (production) ຈິງຈັງ ແນະນຳໃຫ້:
- ເປີດ **Firebase Authentication** ແລ້ວປັບ rule ໃຫ້ຮຽກຮ້ອງການລ໋ອກອິນ ເຊັ່ນ `".read": "auth != null", ".write": "auth != null"`
- ຫຼື ຢ່າງໜ້ອຍຕັ້ງວັນໝົດອາຍຸ (expiration) ໃຫ້ rule ແບບ test-mode ແລ້ວອັບເດດເປັນລະຍະ

### ຂໍ້ຈຳກັດທີ່ຄວນຮູ້
- ຖ້າ 2 ຄົນແກ້ໄຂໂຕະດຽວກັນພ້ອມກັນຄົນລະໜ້າຈໍ (ຫາຍາກ) ອາດຈະມີການທັບຊ້ອນຂໍ້ມູນກັນໄດ້ (last-write-wins,
  ບໍ່ມີລະບົບແກ້ conflict)
- ຖ້າອິນເຕີເນັດຫຼົ່ມ ຫຼື Firebase ໂຫຼດບໍ່ໄດ້, POS ຍັງໃຊ້ງານໄດ້ປົກກະຕິຜ່ານ localStorage (ບໍ່ blocking) —
  ພຽງແຕ່ບໍ່ sync ຂ້າມອຸປະກອນຈົນກວ່າອິນເຕີເນັດຈະກັບຄືນມາ

### 🐛 ແກ້ Bug: ສະຖານະໂຕະປົນກັນ / ຊຳລະບໍ່ໄດ້ (ລວມທັງກໍລະນີເປີດໂຕະໄວ້ດົນ)

ພົບ ແລະ ແກ້ໄຂແລ້ວ **race condition** ໃນລະບົບ sync — ຍິ່ງມີການບັນທຶກຫຼາຍຄັ້ງຕິດກັນ (ຫຼືເປີດໂຕະໄວ້ດົນ ມີການປ່ຽນແປງ
ສະສົມຫຼາຍ) echo ຂອງການບັນທຶກຄັ້ງກ່ອນໜ້າ (ຈາກ Firebase) ອາດຈະມາຮອດຊ້າກວ່າຄັ້ງຫຼັງ ແລະ ໄປທັບຂໍ້ມູນຫຼ້າສຸດ
ເຮັດໃຫ້ໂຕະກັບຄືນເປັນສະຖານະເກົ່າ (ຕົວຢ່າງ: ຈ່າຍບິນສຳເລັດແລ້ວ ແຕ່ໂຕະກັບໄປສະແດງເປັນ "ກຳລັງເລ່ນ" ຄືເກົ່າ, ກົດ
ຊຳລະອີກຄັ້ງບໍ່ໄດ້) — ✅ ແກ້ໄຂໂດຍປ່ຽນວິທີກວດຈັບ "echo ຂອງຕົນເອງ" ຈາກປຽບທຽບເນື້ອຫາຂໍ້ມູນ (ຜິດພາດເມື່ອລຳດັບການ
ມາຮອດສັບສົນ) ໄປເປັນການຕິດປ້າຍ "ລະຫັດອຸປະກອນ" (origin ID) ໃສ່ທຸກຄັ້ງທີ່ບັນທຶກ — ຮັບປະກັນວ່າອຸປະກອນຈະບໍ່ຮັບເອົາ
ຂໍ້ມູນຂອງຕົນເອງກັບຄືນມາທັບຂໍ້ມູນຫຼ້າສຸດ ບໍ່ວ່າ echo ຈະມາຮອດຊ້າ/ໄວປານໃດ. ໄດ້ຂຽນ test ຈຳລອງສະຖານະການນີ້ (ສົ່ງ
echo ແບບຮຽງລຳດັບຍ້ອນຫຼັງທີ່ຮ້າຍແຮງທີ່ສຸດ) ຢືນຢັນວ່າແກ້ໄຂໄດ້ຖືກຕ້ອງແລ້ວ.

ນອກຈາກນັ້ນ ຍັງແກ້ໄຂ **ໜ້າຈໍລ໋ອກອັດຕະໂນມັດ** ໃຫ້ບໍ່ລ໋ອກໜ້າຈໍຂະນະໜ້າຈ່າຍເງິນເປີດຢູ່ (ກັນຂັດຂວາງການຊຳລະ), ແລະ
ໂຫຼດຂໍ້ມູນຫຼ້າສຸດຄືນໃໝ່ອັດຕະໂນມັດທຸກຄັ້ງຫຼັງປົດລ໋ອກ — ປ້ອງກັນຂໍ້ມູນຄ້າງເກົ່າໃນໜ້າຈໍຫຼັງຈາກເປີດຄ້າງໄວ້ດົນ.

### 🐛 ແກ້ Bug ໃໝ່ (ສາເຫດແທ້ຈິງ): "login ໄປໄລຍະໜຶ່ງແລ້ວ ເພີ່ມລາຍການ/ກົດຫຍັງບໍ່ໄດ້"

ພົບສາເຫດແທ້ຈິງແລ້ວ — ບໍ່ແມ່ນເລື່ອງ lock screen ຫຼືການ login ໂດຍກົງ, ແຕ່ແມ່ນ **ຜົນຂ້າງຄຽງຂອງ Firebase
realtime sync ເອງ**: ທຸກຄັ້ງທີ່ມີການປ່ຽນແປງຈາກ *ອຸປະກອນອື່ນ* (ເຖິງແມ່ນບໍ່ກ່ຽວຂ້ອງກັນ ເຊັ່ນ ຄົນອື່ນແກ້ໄຂສະຕັອກ
ຢູ່ອີກເຄື່ອງໜຶ່ງ), ໜ້າຈໍຈະຖືກ render ໃໝ່ທັນທີ — ຊຶ່ງຈະ **ລຶບ input ທີ່ພິມຄ້າງຢູ່** (ເຊັ່ນ ກຳລັງພິມຊື່ລາຍການ
ອາຫານ) ຫຼື ປ່ຽນ DOM ໃຕ້ນິ້ວມືທີ່ກຳລັງຄລິກຢູ່ໃນ modal — ຍິ່ງໃຊ້ໄປດົນ/ຍິ່ງມີຫຼາຍອຸປະກອນ ຍິ່ງມີໂອກາດຊົນກັນຫຼາຍ
(ພິສູດ ແລະ ຢືນຢັນແລ້ວດ້ວຍການທົດສອບ: ພິມຊື່ລາຍການ, ຈຳລອງອຸປະກອນອື່ນສົ່ງຂໍ້ມູນເຂົ້າມາລະຫວ່າງນັ້ນ → ຂໍ້ຄວາມທີ່
ພິມຫາຍ 100%).

✅ **ວິທີແກ້:** ຕອນນີ້ຖ້າຜູ້ໃຊ້ກຳລັງພິມຢູ່ (ມີ input/textarea/select focus ຢູ່) ຫຼື ມີ modal ໃດໜຶ່ງເປີດຄ້າງຢູ່,
ຂໍ້ມູນທີ່ Sync ເຂົ້າມາຈະ **ພັກລໍຖ້າກ່ອນ** (ບໍ່ໄປແກ້ໜ້າຈໍທັນທີ) ຈົນກວ່າຜູ້ໃຊ້ຈະພິມ/ໃຊ້ modal ແລ້ວ ຈຶ່ງອັບເດດ
ໜ້າຈໍ — ຂໍ້ມູນບໍ່ເສຍ (ຍັງ sync ຄົບ), ພຽງແຕ່ບໍ່ໄປລົບກວນຂະນະກຳລັງໃຊ້ງານ. ໄດ້ທົດສອບຢືນຢັນ: ພິມຄ້າງລະຫວ່າງມີ
ຂໍ້ມູນເຂົ້າມາ → ຂໍ້ຄວາມທີ່ພິມຍັງຢູ່ຄົບ ✔️, ປິດ modal/ພິມແລ້ວ → ຂໍ້ມູນທີ່ພັກໄວ້ອັບເດດຄົບຖ້ວນອັດຕະໂນມັດ ✔️

### 🛡️ ຈຸດເຊັກ (Checkpoints) ປ້ອງກັນຄ້າງ/Freeze

ເພີ່ມ "ຈຸດເຊັກ" ໃນຟັງຊັນສຳຄັນທີ່ກ່ຽວກັບການເປີດໂຕະ/ເພີ່ມລາຍການ/ຊຳລະເງິນ (`App.addItem`, `App.removeItem`,
`App.updateItem`, `App.openTableForGame`, `openTableModal`, `App.openPaymentModal`, `App.confirmPayment`):
- ກວດ session ຜູ້ໃຊ້ (`currentUser`) ກ່ອນເຮັດວຽກ — ຖ້າ session ຫາຍໄປ ຈະສະແດງຂໍ້ຄວາມ ແລະ ພາກັບໄປໜ້າ login
  ແທນທີ່ຈະລົ້ມເຫຼວແບບງຽບໆ (silent fail)
- ຫຸ້ມ try/catch — ຖ້າມີ error ບໍ່ຄາດຄິດເກີດຂຶ້ນ, ຈະສະແດງຂໍ້ຄວາມແຈ້ງເຕືອນ ແລະ ບັນທຶກ log ໃນ console ແທນທີ່ຈະ
  ເຮັດໃຫ້ໜ້າຈໍຄ້າງ/ບໍ່ຕອບສະໜອງອີກຕໍ່ໄປ

## 📊 Google Sheets Sync — ບັນທຶກບິນອັດຕະໂນມັດເປັນ Spreadsheet

ນອກຈາກ Firebase, POS ນີ້ຮອງຮັບການສົ່ງບິນ (ທຸກຄັ້ງທີ່ຊຳລະສຳເລັດ) ໄປບັນທຶກເປັນແຖວໃໝ່ໃນ **Google Sheet**
ຂອງທ່ານເອງໂດຍກົງນຳ — ເໝາະສຳລັບເຈົ້າຂອງຮ້ານທີ່ຢາກເບິ່ງ/ວິເຄາະຍອດຂາຍຜ່ານ Sheets ທີ່ຄຸ້ນເຄີຍ, ຫຼືແບ່ງປັນ
ໃຫ້ນັກບັນຊີເບິ່ງໄດ້ງ່າຍ ໂດຍບໍ່ຕ້ອງເປີດແອັບ POS.

ວິທີການເຮັດວຽກ: ໃຊ້ **Google Apps Script Web App** ເປັນຕົວກາງ (ຟຣີ, ຂອງ Google ເອງ, ບໍ່ຕ້ອງມີ server
ຂອງທ່ານເອງ) — POS ຈະສົ່ງຂໍ້ມູນບິນໄປຫາ URL ນີ້ ແລ້ວ Script ຈະບັນທຶກລົງ Sheet ໃຫ້ອັດຕະໂນມັດ.

### ຂັ້ນຕອນການຕັ້ງຄ່າ (ເຮັດຄັ້ງດຽວ)

1. **ສ້າງ Google Sheet ໃໝ່** — ໄປທີ່ [sheets.google.com](https://sheets.google.com) → ສ້າງ Sheet ໃໝ່
   (ຕັ້ງຊື່ຫຍັງກໍໄດ້ ເຊັ່ນ "BK Snooker Bills")
2. **ເປີດ Apps Script Editor** — ໃນ Sheet ນັ້ນ, ເມນູ **Extensions → Apps Script**
3. **ວາງໂຄ້ດ** — ລຶບໂຄ້ດຕົວຢ່າງ (`function myFunction(){}`) ທັງໝົດອອກ, ແລ້ວສຳເນົາເນື້ອຫາທັງໝົດຈາກໄຟລ໌
   `google-apps-script/Code.gs` (ຢູ່ໃນ package ນີ້) ໄປວາງແທນ
4. **Deploy ເປັນ Web App** — ກົດປຸ່ມ **Deploy → New deployment**
   - ກົດຮູບເຟືອງ ⚙️ ຂ້າງ "Select type" → ເລືອກ **Web app**
   - **Execute as:** Me (ບັນຊີ Google ຂອງທ່ານ)
   - **Who has access:** Anyone
   - ກົດ **Deploy**
5. **ອະນຸຍາດສິດ** — Google ຈະຖາມສິດອະນຸຍາດ (Authorize access) — ເລືອກບັນຊີ Google ຂອງທ່ານ ແລະ ກົດ
   "Allow" (ອາດຈະຂຶ້ນຄຳເຕືອນ "Google hasn't verified this app" ເພາະເປັນ script ຂອງທ່ານເອງ — ກົດ
   "Advanced" → "Go to (ຊື່ project) (unsafe)" → "Allow" ໄດ້ເລີຍ, ປອດໄພເພາະເປັນ script ຂອງທ່ານເອງ)
6. **ສຳເນົາ Web app URL** — ຫຼັງ Deploy ສຳເລັດ ຈະໄດ້ URL ໜ້າຕາປະມານ:
   ```
   https://script.google.com/macros/s/AKfycb.../exec
   ```
7. **ວາງໃນ POS** — ເປີດ POS → ⚙️ ຕັ້ງຄ່າ → ກ່ອງ **"📊 Google Sheets — ບັນທຶກບິນອັດຕະໂນມັດ"** → ວາງ URL
   → ກົດ **ບັນທຶກ** → ກົດ **🔌 ທົດສອບການເຊື່ອມຕໍ່** ເພື່ອກວດວ່າເຮັດວຽກ (ຄວນເຫັນແຖວ "TEST" ຂຶ້ນໃນ Sheet)

ຫຼັງຈາກນັ້ນ ທຸກຄັ້ງທີ່ພະນັກງານກົດ "✅ ຢືນຢັນຊຳລະ" ໃນ POS, ບິນຈະຖືກເພີ່ມເປັນແຖວໃໝ່ໃນ Google Sheet ໂດຍອັດຕະໂນມັດ
(ຊື່ tab "Bills" ຈະຖືກສ້າງໃຫ້ອັດຕະໂນມັດ ພ້ອມຫົວຖັນ) — ບອກ: ເລກບິນ, ໂຕະ, ເວລາ, ລາຍການ, ຄ່າໂຕະ/ອາຫານ,
ສ່ວນຫຼຸດ, ຍອດລວມ, ວິທີຈ່າຍ, ພະນັກງານ.

> ⚠️ **ຂໍ້ຈຳກັດ:** ຍ້ອນ Google Apps Script ບໍ່ໄດ້ຕັ້ງ CORS header ໃຫ້ browser ອ່ານຄຳຕອບກັບຄືນໄດ້, POS ຈຶ່ງ
> ສົ່ງຂໍ້ມູນແບບ "ຍິງແລ້ວລືມ" (fire-and-forget) — ຄຳຂໍຍັງໄປຮອດ ແລະ ບັນທຶກລົງ Sheet ໄດ້ປົກກະຕິ, ພຽງແຕ່ POS
> ຈະບໍ່ຮູ້ທັນທີວ່າສຳເລັດ/ລົ້ມເຫຼວ (ຕ້ອງເປີດ Sheet ເບິ່ງເອງເພື່ອຢືນຢັນ). ນີ້ບໍ່ກະທົບການອອກໃບເສັດ/ການເຮັດວຽກ
> ຫຼັກຂອງ POS ເລີຍ — ເປັນພຽງການບັນທຶກສຳຮອງເພີ່ມເຕີມເທົ່ານັ້ນ.
>
> ນອກນັ້ນ Google Sheets ບໍ່ແມ່ນ realtime ແບບ Firebase — ໃຊ້ເປັນບ່ອນ "ບັນທຶກ/ລາຍງານ" ເທົ່ານັ້ນ (write-only
> ຈາກ POS), ບໍ່ໄດ້ໃຊ້ sync ຂໍ້ມູນໂຕະ/ສະຕັອກ/ຕັ້ງຄ່າກັບຄືນມາຫາ POS ແບບ Firebase.

## ▶️ ວິທີ Run ຢູ່ຄອມພິວເຕີຂອງທ່ານ (Local)

ແອັບນີ້ໃຊ້ Service Worker ແລະ `fetch()` ບາງສ່ວນ, ຊຶ່ງ browser ບໍ່ອະນຸຍາດໃຫ້ໃຊ້ຜ່ານການເປີດໄຟລ໌ໂດຍກົງ
(`file://...`) ໄດ້ 100% (ບາງ feature ອາດຈະບໍ່ເຮັດວຽກ) — ດັ່ງນັ້ນ ແນະນຳໃຫ້ເປີດຜ່ານ **local web server** ນ້ອຍໆ
ດັ່ງລຸ່ມນີ້ (ເລືອກອັນໃດອັນໜຶ່ງ, ອັນໃດກໍ່ໄດ້):

### ວິທີ 1 — ໃຊ້ Python (ມີຢູ່ໃນ Windows/Mac/Linux ສ່ວນຫຼາຍແລ້ວ)
```bash
# ໄປຫາໂຟນເດີໂປຣເຈັກກ່ອນ
cd path/to/BK-Snooker-POS

# ຖ້າມີ Python 3
python3 -m http.server 8080

# ຖ້າ Windows ໃຊ້ຄຳສັ່ງ
python -m http.server 8080
```
ຈາກນັ້ນເປີດ browser ໄປທີ່ **http://localhost:8080**

### ວິທີ 2 — ໃຊ້ Node.js (ຖ້າມີ Node ຕິດຕັ້ງແລ້ວ)
```bash
npx serve .
```
ຈາກນັ້ນເປີດ link ທີ່ terminal ສະແດງ (ປົກກະຕິ http://localhost:3000)

### ວິທີ 3 — ໃຊ້ VS Code + Live Server
1. ເປີດໂຟນເດີໂປຣເຈັກໃນ VS Code
2. ຕິດຕັ້ງ extension ຊື່ **"Live Server"**
3. ຄລິກຂວາທີ່ `index.html` → **Open with Live Server**

## 🌐 ວິທີ Deploy ຂຶ້ນ GitHub Pages (ໃຫ້ໃຊ້ໄດ້ຜ່ານອິນເຕີເນັດ ຟຣີ)

1. ສ້າງ repository ໃໝ່ໃນ GitHub (ຕົວຢ່າງຊື່: `bk-snooker-pos`)
2. ອັບໂຫຼດ (upload/push) ໄຟລ໌ທັງໝົດໃນໂຟນເດີນີ້ (`index.html`, `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`)
   ໄປໃສ່ root ຂອງ repo — ຕົວຢ່າງດ້ວຍ Git:
   ```bash
   git init
   git add .
   git commit -m "BK Snooker POS V4 - fixed bugs"
   git branch -M main
   git remote add origin https://github.com/<ຊື່ບັນຊີຂອງທ່ານ>/bk-snooker-pos.git
   git push -u origin main
   ```
   (ຫຼືອັບໂຫຼດຜ່ານໜ້າເວັບ GitHub ໂດຍກົງ: ໜ້າ repo → **Add file → Upload files**)
3. ໄປທີ່ repo → **Settings → Pages**
4. ໃນຫົວຂໍ້ **Source** ເລືອກ branch `main` ແລະ folder `/ (root)` → ກົດ **Save**
5. ລໍຖ້າປະມານ 1–2 ນາທີ, GitHub ຈະໃຫ້ link ມາລັກສະນະ:
   ```
   https://<ຊື່ບັນຊີຂອງທ່ານ>.github.io/bk-snooker-pos/
   ```
6. ເປີດ link ນັ້ນຜ່ານມືຖື/ຄອມ — ສາມາດກົດ **"Add to Home Screen"** ເພື່ອຕິດຕັ້ງເປັນແອັບໄດ້ (PWA)

## 💾 ຂໍ້ມູນເກັບໄວ້ໃສ?

ຂໍ້ມູນທັງໝົດ (ໂຕະ, ບິນ, ສະຕັອກ, ສະມາຊິກ, ...) ຖືກເກັບໄວ້ໃນ **`localStorage`** ຂອງ browser ໃນອຸປະກອນນັ້ນ —
ໝາຍຄວາມວ່າ:
- ຂໍ້ມູນຈະ**ບໍ່**ຫາຍໄປເມື່ອປິດ/ເປີດ browser ໃໝ່ (ຄົງຢູ່ໃນອຸປະກອນນັ້ນ)
- ຖ້າລ້າງ browser cache/data ຫຼືປ່ຽນອຸປະກອນ/browser ອື່ນ ຂໍ້ມູນຈະ**ບໍ່ຕິດຕາມມາ**
- ແນະນຳໃຫ້ໃຊ້ຟັງຊັນ **ສຳຮອງ/Backup** ພາຍໃນແອັບ (ໜ້າ ⚙️ ຕັ້ງຄ່າ) ເປັນປະຈຳ ເພື່ອ export ຂໍ້ມູນອອກມາເກັບໄວ້
